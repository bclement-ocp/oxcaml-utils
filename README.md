A collection of utilities and scripts to build and benchmark OxCaml. Work in
progress.

# ox.py

This script is a swiss-knife utility for the OxCaml compiler developer.

## Revision syntax

The syntax for OxCaml revisions is either `rev` (equivalent to
`rev@oxcaml/oxcaml`), `rev@user` (equivalent to `rev@user/oxcaml`), or
`rev@user/repo`.

**Note:** The syntax used by the `ox.py` script is different from the legacy
syntax used by other scripts and s closer to what tools like `git` and `jj` use. 

### Default revision

`ox.py` uses a default revision of OxCaml. The default revision can be
configured using the `OXCAML_REVISION` environment variable, or with the `-r`
toplevel flag (e.g. `ox.py -r 5.4.0-ox2 ...`).

If no default revision is provided, a hard-coded release tag is used.

## Utility commands

`ox.py` provides some utility commands that can be used to facilitate the use of
specific, potentially unreleased, versions of OxCaml.

### ox.py shell

The `shell` subcommand drops the user into a shell where the provided revision
of OxCaml is installed.

#### Example

To enter a shell where OxCaml 5.4.0-ox2 is available:

```console
$ ox.py -r 5.4.0-ox2 shell
```

### ox.py ocamlopt

The `ocamlopt` (or `opt`) subcommand runs a specific version of `ocamlopt`.

#### Example

To compile `file.ml` with OxCaml 5.4.0-ox2:

```console
$ ox.py -r 5.4.0-ox2 ocamlopt file.ml
```

## Benchmarking commands

`ox.py` provides commands to benchmark a specific version of the OxCaml
compiler. Currently, the only benchmark supported is the build of the default
revision of OxCaml.

### Caching

The results of most benchmark operations are cached by `ox.py`. This ensures
that we don't need to re-compute the results of a given benchmark to perform
multiple comparisons, for instance.

When cached results are used, a message providing the path to the file
containing the cached results is displayed. To force a recomputation, the cached
file must be manually deleted or moved.

### Compiler configuration

Each benchmark operates using a given *compiler configuration*, which is
combination of values for `OCAMLPARAM` parameters and command-line flags to use.

The syntax for defining benchmark configurations is shared across the commands
below and can be controlled using flags provided *after* the name of the
revision to use for the benchmark.

`OCAMLPARAM` parameters can be provided using `-P name=value` while command-line
flags can be passed using the `-F` prefix (this behaves similarly to e.g. linker
flags passed with `-L`).

For instance, the following command will record a profile with a specific
`OCAMLPARAM` value set:

```console
$ ox.py profile report my-feature -P my-ocamlparam=my-value
```

and the following command will use a command-line flag instead:

```console
$ ox.py profile report my-feature -F -my-flag -F my-value
```

### ox.py profile

`ox.py profile` is a command to manipulate the profiling (timing) information
recorded during a benchmark using the built-in compiler profiling
infrastructure.

#### ox.py profile report

`ox.py profile report` can be used to report profiling (timing) information
during a benchmark.

The hierarchical report includes the total time spent in different compiler
passes (as used by `-dprofile`), along with a percentage of the *total
compilation time* spent in each pass. The passes are ordered by (decreasing)
time spent.

```console
$ ox.py profile report my-feature
552.76s 100.0%
  + 336.70s  60.9% generate
  |   + 199.56s  36.1% flambda2
  |   |   + 177.80s  32.2% simplify
  |   |   |   +  59.63s  10.8% other
  |   |   |   +  57.74s  10.4% speculative_inlining
...
```

### ox.py fexpr

`ox.py fexpr` is a command to manipulate the fexpr (intermediate representation)
dumps recorded during a benchmark.

The `-j` (or `--jobs`) flag can be used to control the parallelism of the
benchmark, e.g. `ox.py fexpr -j 16` will run using `16` parallel jobs.

#### ox.py fexpr diff

`ox.py fexpr diff` can be used to compare the fexpr dumps generated by two
different compiler configurations.

This command outputs a diff in a format similar to that of the `patdiff` tool.

# oxcaml-shell.py

This script allows to setup a shell ready to build OxCaml with another version
of OxCaml as the system compiler (note: you will need to pass
`--disable-optional-checks` when running `./configure`).

To build and enter a shell where the system compiler is release 5.2.0minus-37
from the `oxcaml/oxcaml` GitHub repo:

```console
$ python3 oxcaml-shell.py 5.2.0minus-37
```

To build and enter a shell where the system compiler comes from a specific
branch in a fork:

```console
$ python3 oxcaml-shell.py my-username/my-custom-tag
```

If the repository is not called `oxcaml` it must be specified:

```console
$ python3 oxcaml-shell.py my-username/flambda-backend/my-custom-tag
```

The syntax is either `user/repo/rev`, `user/rev` (equivalent to
`user/oxcaml/rev`), or `rev` (equivalent to `oxcaml/oxcaml/rev`).

# bench.py

This script (intended to be run from inside a shell created with
`oxcaml-shell.py`) allows to benchmark the build of a specific version of the
oxcaml compiler using whatever compiler is currently available in the
environment.

It can be used as:

```console
$ python3 bench.py oxcaml/main -o path/to/where/output/is
```

which will collect profile information (profile csvs) in the provided output directory.

OCAMLPARAM and compilation flags can be passed using `-p` and `-f`:

```console
$ python3 bench.py oxcaml/main -o path/to/where/output/is \
    -p my-param=my-value -f-my-flag -f my-flag-value
```
